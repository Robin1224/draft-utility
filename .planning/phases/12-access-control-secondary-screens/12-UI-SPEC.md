## Component Contracts

All three screens are extracted as **presentational** components under `src/lib/components/molecules/` — they must not import `$live/*`, so the browser vitest project can render them (`phase11-fixes.spec.js:4-6` documents why `+page.svelte` itself cannot be rendered). Each takes plain props and callbacks. Svelte 5 runes + JSDoc; **no TypeScript**.

### 1. `CyConnecting.svelte` (SCR-01)

```
.cy-loading                                   (grid, place-items center, min-height 78vh)
└── .cy-loading-card [.is-timeout]            (max-width 560px, violet inset glow)
    ├── .cy-loading-eyebrow                   "$ ./draftnet --status"
    ├── h2                                    "ESTABLISHING_LINK" + <span.cy-dots aria-hidden>
    │                                         │ timed out → "LINK_TIMEOUT", no dots span
    ├── pre.cy-loading-log                    {log.text}
    │                                         + <span.cy-chat-cursor aria-hidden>▮</span>  while !done && !timedOut
    │                                         + {'\n'}<span.cy-err>[FAIL] …</span>          while timedOut
    ├── .cy-loading-meter    (not timed out)   → .cy-loading-bar > b(█×40) + .cy-loading-pct "sync…"
    └── .cy-loading-actions  (timed out)       → button.cy-btn.cy-btn-primary "$ RETRY_LINK()"
                                               + p.cy-foot "// the room may still be live — retry the link"
```

| Aspect | Contract |
|--------|----------|
| Props | `{ code: string, timedOut?: boolean, onRetry: () => void }` — `timedOut` is the browser-spec seam for D-08 |
| Log | `createTypedLog(connectLines(code), { speed: 7, lineGap: 120 })` (Phase 9 factory, pre-specified for this screen). Call `log.stop()` in an `$effect` teardown |
| Log colouring | The typed log is **one uncoloured text node by construction** — `createTypedLog` yields a single string, so per-token spans are impossible while typing. The ported `.cy-loading-log b` and `.cy-loading-log .cy-wait` declarations stay unused (fidelity port only). **Do not** try to colourize the typed log; the `.cy-err` tail is a *sibling* span appended after `{log.text}` |
| Truncation | The screen is normally dismissed **mid-log**: a full type takes **2594 ms** while the D-05 floor is **900 ms** (≈ line 1 + `[ .. ] resolving host ............`). The design must read correctly truncated — that is what the trailing `▮` is for, and what `min-height: 8.4em` on the well is for (no layout jump, no reflow on dismissal) |
| Meter honesty | Decorative, indeterminate (D-07). `aria-hidden="true"` on `.cy-loading-bar`. **Never** `role="progressbar"` — there is no progress value to report (one socket open, one snapshot) |
| Timeout swap | On `timedOut`, the meter is **replaced** by `.cy-loading-actions`. An animating progress meter under a dead socket is dishonest, so the animation must be gone, not merely captioned |
| Timeout timing | `timedOut` can only be true at ≥ 10 s, which is > 2594 ms, so the `[FAIL]` line always appends to a **complete** 6-line log and the `▮` is already gone. No half-typed failure state exists |
| Retry semantics | `onRetry` performs a **full page reload** (`location.reload()`), not `invalidateAll()`. Rationale (RESEARCH Investigation 5): a hung stream store exposes no `refetch` and `invalidateAll()` re-runs only HTTP loads — a new client and a new socket are the only reliable reset for a connect that never resolved. The component only calls the prop; the page owns the mechanism |
| Owner state (page) | `CONNECT_FLOOR_MS = 900` (D-05), `CONNECT_TIMEOUT_MS = 10_000` (D-08), both as mount-time latches. `showConnecting = !gated && !loadError && (loading \|\| !floorElapsed)` |

### 5. Page + shell integration (`+page.svelte`, `+layout.svelte`)

Branch order is load-bearing (RESEARCH Pattern 4) — the UI contract depends on it:

```
1. {#if gated}                          → CyGuestGate     (reads NO stream value)
2. {:else if snapshot?.phase === 'cancelled'} → CyCancelled
3. {:else if showConnecting}            → CyConnecting
4. {:else if loadError}                 → existing error copy (NOT the gate, NOT connecting)
5. {:else if snapshot}                  → drafting | review | lobby   ('cancelled' removed from the drafting condition)
```

- Placing `cancelled` **above** `showConnecting` stops a dead room flashing `ESTABLISHING_LINK` during the floor window.
- `DraftBoard`'s `.cy-draft-cancelled` sub-branch and its `cancelledTeam` / `cancelledTeamLabel` derives are **deleted** in the same task that adds branch 2 — two competing cancelled UIs would otherwise double-render (RESEARCH Pitfall 10).
- **`src/routes/+layout.svelte`** (the *root* layout — the only one in the project) gates its `fromStore(lobby(code))` read at **line 17** on `page.data.gated`; without it the gate is a poison pill and `RETRY_AS_GUEST()` can never succeed. **Do not create `src/routes/draft/[id]/+layout.svelte`** — a second subscriber to the same refcounted store re-opens the very leak this gate closes.
- **The chat `$effect` at `+page.svelte:181-192` gets a `gated` guard** (`if (gated) return;`). This sits *outside* the branch chain above — it subscribes on mount regardless of which branch renders — so a gated guest would otherwise keep receiving all-channel chat for a room they cannot see. This is D-20's client-side half; the authoritative `chatAll` / `chatSpectators` room-privacy guard in `src/live/chat.js` is server-side and out of this spec's remit, but the two ship together and mirror D-01's two-layer model (SSR/client = UX, server = boundary).
- **`ChatPanel` is NOT rendered on the cancelled screen.** `+page.svelte:265-278` currently renders it for `phase === 'drafting' || phase === 'cancelled'`; splitting `cancelled` into branch 2 removes the chat sidebar from a dead room. This is prototype-faithful (`CYCancelled` has no chat) and intended — stated explicitly because it removes a currently-shipped surface, so neither an executor nor the UI auditor should read it as a regression and re-add it.
