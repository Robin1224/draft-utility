## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| application → Postgres (Drizzle/Neon) | All room and membership writes cross here; the only durable store of `is_public` |
| caller → `rooms.js` service helpers | `src/live/*` RPCs pass a caller-supplied `hostUserId` and payload into these helpers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-04 | Tampering | `setRoomVisibilityAsHost` `.set()` | mitigate | `.set()` receives an explicit `{ is_public, updated_at }` literal — never a spread of a caller payload. Mass assignment on the `room` table is structurally impossible. Asserted by the set-payload capture test |
| T-12-04b | Elevation of privilege | `setRoomVisibilityAsHost` | mitigate | `assertHost(roomRow, hostUserId)` runs against the freshly selected row **before** the update; throws the `NOT_HOST` sentinel. Asserted by the non-host rejection test |
| T-12-07 | Information disclosure | stale `room_member` guest rows on a room flipped private | mitigate | `removeGuestSpectators` bulk-deletes `guest_id IS NOT NULL` rows so an ejected guest is not server-side-resident and cannot reappear in any snapshot after a reconnect |
| T-12-07b | Information disclosure | over-broad ejection deleting signed-in spectators | mitigate | Predicate is `isNotNull(room_member.guest_id)`, not `team IS NULL`. Asserted by the delete-predicate test |
| T-12-15 | Tampering (SQL injection) | new column read/write, bulk delete | mitigate | Drizzle parameterized builders only (`eq`, `and`, `isNotNull`). No raw `sql` template added by this plan |
| T-12-16 | Information disclosure | `is_public` defaulting open for pre-existing rows | mitigate | `DEFAULT false NOT NULL` in a single `ADD COLUMN` back-fills every existing row closed; `createRoom` sets nothing so new rooms inherit the same default (ACC-01 "defaulting to closed" holds at both ends) |
| T-12-SC | Tampering | npm/pip/cargo installs | accept | This phase installs zero packages (`12-RESEARCH.md` § Package Legitimacy Audit: not applicable, verified against `package.json`). No install task exists in any Phase 12 plan, so no slopcheck gate applies |
