# Phase 8 — UI Design Contract: Cyber Foundation & App Shell

> Visual and interaction contract for the Cyber design-system foundation and the persistent terminal chrome (app shell) that every later screen sits inside. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase is NOT individual screens.** It locks the design tokens, typography, the zero-radius/1px-border rules, and the persistent shell (header + brand + blinking cursor + phase tracker + room-code copy + scanlines + scrolling body). Screen reskins are Phase 10; the plasma shader is Phase 9 (Phase 8 leaves a mount point only).
>
> **Authoritative source — port VERBATIM:** `design_handoff_pickban_cyber/prototype/variants/cyber.css`. Every hex, glow shadow, gradient, and `.cy-*` rule below is transcribed from it. Do NOT approximate — these values are load-bearing for fidelity (CONTEXT D-03).
>
> **Requirements covered:** DS-01, DS-02, DS-03, DS-04, DS-05, FX-05.

## Typography

Everything is monospace (`--cy-mono`). Headings/labels are frequently UPPERCASE with tracked letter-spacing. Phase 8 shell uses a small, dense scale. (Larger display/title sizes from `cyber.css` belong to Phase 10 screens and are out of scope here.)

| Role | Size | Weight | Line Height | Letter-spacing | Where (shell scope) |
|------|------|--------|-------------|----------------|---------------------|
| Header / chrome text | 12px | 400 | normal | — | `.cy-header` base font-size |
| Brand wordmark name | 12px | **700** | normal | `0.1em` | `.cy-brand-name` (+ lime glow) |
| Phase tracker entry | 12px | 400 | normal | — | `.cy-phase` (inherits header 12px) |
| Room-code meta | 12px | 400 | normal | — | `.cy-meta-key` / `.cy-meta-val` |
| Copy button | 12px | 400 | normal | — | `.cy-meta-copy` (`font: inherit`) |

**Declared weights (exactly the 4 the font must ship — per DS-01):** 400 (regular body / chrome), 500, 600, 700 (brand). The shell visibly uses **400** and **700**; 500/600 are loaded for downstream screens. All four woff2 weights MUST be present (DS-01).

**Line-height note:** chrome text uses the browser default (compact); this is a deliberately dense terminal readout, not prose. Body-copy line-heights (1.5–1.6) appear on later-phase screens, not the shell.

- Set `font-family: var(--cy-mono)` on `.cy-app` so the whole app inherits it (no other UI font remains — DS-01).

## Spacing Scale

The Cyber direction uses small, terminal-dense spacing. Values transcribed from `cyber.css` shell rules. All are multiples of 4 except the deliberate `12px`/`20px` chrome paddings which ARE multiples of 4.

| Token | Value | Usage (shell scope) |
|-------|-------|---------------------|
| 2xs | 4px | `.cy-brand` gap; `.cy-brand-cur` margin-left; tight inline gaps |
| xs | 8px | `.cy-meta` gap; copy-button vertical padding region |
| sm | 12px | `.cy-header` vertical padding (`12px 20px`) |
| md | 16px | `.cy-phases` gap |
| lg | 20px | `.cy-header` horizontal padding (`12px 20px`) |
| copy-btn | `4px 8px` | `.cy-meta-copy` padding |

**Borders:** always **1px** (`border-bottom: 1px solid var(--cy-line)` on header; 1px on copy button). Occasional 3px colored left-border accents exist on later screens — out of scope for the shell.

**Border-radius: 0 everywhere (DS-04).** Zero rounding on every surface, button, input, and panel. "Rounding" is expressed through ASCII box-drawing glyphs, never `border-radius`. This is a hard global rule applied at the foundation level.

Exceptions: none.

## App Shell Structure (DS-05)

Port the `CYChrome` DOM (cyber.jsx §CYChrome, lines ~153–182) to Svelte 5, with the CONTEXT overrides applied. The shell is the single persistent chrome wrapping every route (wired via `+layout.svelte` or a chrome component it renders — planner's call, CONTEXT discretion).

**DOM hierarchy (`.cy-app` is the styling + token root):**

```
.cy-app                          (flex column; overflow hidden; relative; radial-gradient bg)
├── <shader mount point>         (Phase 9 fills this — Phase 8 leaves an EMPTY .cy-shader slot/component; NO shader rendered)
├── .cy-scanlines                (FX overlay — IN SCOPE; see below)
├── header.cy-header             (grid 1fr auto 1fr; border-bottom 1px; bg --cy-bg-2; 12px 20px)
│   ├── .cy-brand                (left column)
│   │   ├── .cy-brand-bracket    "["   (violet)
│   │   ├── .cy-brand-name       "DRAFT_EM"  (lime, weight 700, lime glow, letter-spacing 0.1em)
│   │   ├── .cy-brand-bracket    "]"   (violet)
│   │   └── .cy-brand-cur        "▮"   (lime, blinking — FX-05)
│   ├── .cy-phases               (center column; flex gap 16px)
│   │   └── .cy-phase × 3        "01_LOBBY" "02_DRAFTING" "03_REVIEW" (zero-padded)
│   └── .cy-meta                 (right column; justify-self end; flex gap 8px)
│       ├── .cy-meta-key         "$ ROOM="  (text-3)
│       ├── .cy-meta-val         {code}      (violet, violet glow)  — shows "—" when no room
│       └── button.cy-meta-copy  "[copy]"    (writes code to clipboard)
└── .cy-body                     (flex:1; overflow:auto; position relative; z-index 1 — the scrolling region all routes render into)
```

### Brand wordmark (CONTEXT D-06 — overrides prototype/README)
- Wordmark = **`[ DRAFT_EM ]`** (the registered domain). NOT the prototype's `DRAFT_NET`, NOT the README's `DRAFT`.
- Structure: violet `[`, lime `DRAFT_EM` (weight 700 + lime glow), violet `]`, then the lime blinking cursor `▮`.

### Phase tracker (CONTEXT D-07 — overrides README's 4-phase)
- **Exactly 3 phases**, mapped 1:1 to `snapshot.phase`:

  | snapshot.phase | Tracker label | Index |
  |----------------|---------------|-------|
  | `lobby` | `01_LOBBY` | 0 |
  | `drafting` | `02_DRAFTING` | 1 |
  | `review` | `03_REVIEW` | 2 |

- Zero-padded numbering (`01_`, `02_`, `03_`) per the prototype pattern `${String(i+1).padStart(2,"0")}_${p}`.
- **Active** phase: `.is-active` → lime + `--cy-lime-glow`.
- **Prior** (done) phases: `.is-done` → `--cy-text-2` (dimmed).
- **Future** phases: base `--cy-text-3`.
- The `cancelled` room phase is **NOT** a tracker step — it is a terminal screen handled in Phase 12. When phase is `cancelled` (or any non-tracked value), no entry is marked active (all render as future/dimmed); do not crash on an unknown phase.

### Room-code meta + copy button (CONTEXT D-09, DS-05)
- `.cy-meta-key` shows `$ ROOM=`; `.cy-meta-val` shows the current room code in violet with violet glow.
- **No-room screens (Home/Login):** the code value shows `—` (em dash) per the prototype.
- `.cy-meta-copy` button (`[copy]`) writes the **current room code** to the clipboard via `navigator.clipboard.writeText(code)`. Hover flips border + text to lime.
- When there is no room (`—`), copy is a no-op / may be disabled — copy only fires with a real code.

### Scanline overlay (FX-05-adjacent — IN SCOPE)
Port `.cy-scanlines` verbatim:
```css
.cy-scanlines {
  position: absolute; inset: 0; pointer-events: none; z-index: 5;
  background: repeating-linear-gradient(0deg, transparent 0 2px, rgba(196, 75, 255, 0.04) 2px 3px);
}
```
Sits above the body content, never intercepts pointer events. Always on.

### Shader mount point (Phase 9 — OUT OF SCOPE, leave a slot)
- Phase 8 renders an **empty `.cy-shader` slot/component** at the top of `.cy-app` so Phase 9 can drop the plasma canvas in without restructuring the shell. No canvas, no animation, no shader logic in Phase 8.
- Keep the `.cy-shader` / `.cy-shader-hot` CSS rules ported (they describe the slot's positioning) but render nothing animated inside.

## Interaction & Motion Contract (FX-05, CONTEXT D-10)

### Blinking block cursor (FX-05 — IN SCOPE)
- The header brand cursor `▮` (`.cy-brand-cur`) blinks via:
  ```css
  .cy-brand-cur { color: var(--cy-lime); animation: cy-blink 1s infinite step-end; margin-left: 4px; }
  @keyframes cy-blink { 50% { opacity: 0; } }
  ```
- 1s period, `step-end` timing (hard on/off, no fade).
- **MUST be suppressed under `prefers-reduced-motion: reduce`** (CONTEXT D-10): wrap the blink in a media query so the cursor renders static (visible, not animated) when reduced motion is set. Mirror the prototype's reduced-motion pattern (`useTypedLog` / the `@media (prefers-reduced-motion: reduce)` block in cyber.css).
  ```css
  @media (prefers-reduced-motion: reduce) {
    .cy-brand-cur { animation: none; }
  }
  ```
- The same `cy-blink` keyframe also serves the chat-input cursor in later phases — declare it once at the foundation level.

### Copy-to-clipboard feedback
- Clicking `[copy]` writes the room code to the clipboard. Optional ephemeral affordance (e.g. brief `[copied]` label swap) is discretion; the hard requirement is the clipboard write succeeds and the button is keyboard-focusable.

### No entrance animation on the shell
- The shell itself has no entrance animation. (Modal/scrim fade-ins are a later phase and intentionally instant anyway.)

## Tailwind Removal Contract (DS-03, CONTEXT D-04/D-05)

Hard cutover in Phase 8. Remove Tailwind from all three wiring points:

| Location | Action |
|----------|--------|
| `package.json` | Remove `tailwindcss`, `@tailwindcss/vite`, `prettier-plugin-tailwindcss` deps |
| `vite.config.js` | Remove the `tailwindcss()` plugin (import + usage); leave sveltekit/uws/realtime/devtoolsJson intact |
| `src/routes/layout.css` | Remove `@import 'tailwindcss';` and the `@theme {…}` block (and the Manrope `@font-face`); replace with the global Cyber stylesheet |

- **No** leftover Tailwind directives, `@apply`, or `@theme`; the app must build cleanly.
- **Accepted interim (D-05):** existing screens/components keep their utility-class strings and render **plain/unstyled** between Phase 8 and their Phase 10 reskin. This visual degradation is expected and acceptable.
- **Hard constraint:** all **130 unit tests must keep passing** (they assert behavior/text, not visuals) and the lobby/draft **snapshot shape is unchanged**. Removing Tailwind must not break either the browser (svelte) or node (server) vitest project's build.
- Global stylesheet location/import (e.g. `src/app.css` imported in `+layout.svelte`, replacing `layout.css`) is discretion.
