# External Integrations

**Analysis Date:** 2026-09-19

## APIs & External Services

**Authentication:**
- Discord OAuth — the **only** social login provider, configured in `src/lib/server/auth.js` (`socialProviders.discord`) using `env.DISCORD_CLIENT_ID` / `env.DISCORD_CLIENT_SECRET`.
  - SDK/Client: `better-auth` (`betterAuth(...).api.signInSocial`), invoked from `src/routes/login/+page.server.js` (`signin` and `register` form actions both call `auth.api.signInSocial({ body: { provider: 'discord', ... } })`).
  - Auth: env vars `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`.
  - No email/password or other social providers are configured — Discord is required to become a `role: 'player'`; unauthenticated visitors are always treated as guests (see Auth & Identity below).

**No other third-party APIs detected** — no payment provider, no analytics/tracking SDK, no email-sending service, no third-party asset CDN calls found in `src/` (only local asset imports and self-hosted fonts under `src/lib/assets/`).

## Data Storage

**Databases:**
- PostgreSQL via **Neon serverless** driver.
  - Connection: `env.DATABASE_URL` (read via `$env/dynamic/private` in `src/lib/server/db/index.js`; read via `process.env.DATABASE_URL` in `drizzle.config.js` since Drizzle Kit runs outside the SvelteKit runtime).
  - Client: `drizzle-orm/neon-http` wrapping `@neondatabase/serverless`'s `neon(...)` HTTP client — `src/lib/server/db/index.js`.
  - ORM: Drizzle ORM (`drizzle-orm ^0.45.1`), schema defined in `src/lib/server/db/schema.js` (app tables: `task`, `room`, `room_member`, `draft_action`) plus `src/lib/server/db/auth.schema.js` (Better Auth tables: `user`, `session`, `account`, `verification` — auto-generated by `npm run auth:schema`, re-exported from `schema.js` via `export * from './auth.schema'`).
  - Migrations: SQL files under `drizzle/` (`0000_omniscient_pixie.sql`, `0001_milky_selene.sql`, `0002_add_room_is_public.sql`) with Drizzle Kit metadata snapshots in `drizzle/meta/`. Managed via `npm run db:generate` / `db:migrate` / `db:push`.
  - The `room.draft_state` column is `jsonb`, storing the live draft script/turn/pause state as a JSON blob (`DraftState` JSDoc typedef in `schema.js`) rather than normalized rows — the source of truth for an in-progress draft round-trips through this single JSON column plus the append-only `draft_action` audit table.

**File Storage:**
- None — no object storage (S3/GCS/etc.) integration found. Static assets (fonts, favicon) are bundled locally under `src/lib/assets/` and `static/`.

**Caching:**
- None — no Redis/Memcached or HTTP cache layer detected. Real-time state lives in-memory in the uWS process (via `svelte-realtime`) and is persisted to Postgres (`room.draft_state`).

## Authentication & Identity

**Auth Provider:**
- Better Auth (`better-auth ~1.4.21`), self-hosted, backed by the Drizzle/Postgres adapter — `src/lib/server/auth.js`.
  - `drizzleAdapter(db, { provider: 'pg' })` — sessions/accounts/users persisted in Postgres via the auth schema tables above.
  - `sveltekitCookies(getRequestEvent)` plugin (must remain last in the `plugins` array per an inline comment) — bridges Better Auth's cookie handling into SvelteKit's request/response cycle.
  - `baseURL: env.ORIGIN`, `secret: env.BETTER_AUTH_SECRET`.
  - Wired into every HTTP request via `handleBetterAuth` in `src/hooks.server.js` (populates `event.locals.session` / `event.locals.user`, then delegates to `svelteKitHandler` for Better Auth's internal routes, e.g. the OAuth callback).
- **Guest identity layer** (custom, not Better Auth): `src/hooks.server.js`'s `guestCookieHandle` sets a long-lived (`400` days) `draft_guest` HttpOnly cookie holding a `crypto.randomUUID()` for anonymous users — used to give unauthenticated spectators/players a stable identity for WebSocket kick-targeting and to link a guest session to a real account after login (D-12/D-13/D-14 references in code comments).
- **WebSocket-time auth**: `src/hooks.ws.js`'s `upgrade({ headers })` re-derives the session at WS upgrade time by wrapping raw headers in a `Headers` object and calling `auth.api.getSession(...)`. Unauthenticated connections are always allowed through as `role: 'guest'` (never rejected). A live RPC function `live.auth.refreshSession` lets an already-connected guest socket upgrade in-place to `role: 'player'` after completing Discord OAuth in a separate browser tab/request — avoiding a WS reconnect.
