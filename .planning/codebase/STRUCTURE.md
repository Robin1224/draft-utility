## Directory Purposes

**`src/live/`:**
- Purpose: The entire realtime RPC/pubsub surface of the app — every WebSocket-callable function and stream
- Contains: `.js` modules exporting `live(...)`/`live.stream(...)` handlers; co-located `.spec.js` tests
- Key files: `room.js` (lobby + host operations + disconnect grace), `draft.js` (pick/ban + timers), `chat.js` (channels + moderation), `draft-timers.js` (shared timer state, intentionally import-light)
- Special: this directory is scanned by the `svelte-realtime/vite` plugin to generate the `$live` import alias and `src/live/$types.d.ts`; do not rename without checking `vite.config.js`'s `realtime()` plugin behavior

**`src/lib/server/`:**
- Purpose: Server-only domain logic and DB access, importable by both HTTP routes and `src/live/*`
- Contains: `rooms.js`, `draft.js`, `room-lifecycle.js`, `auth.js`, `db/`
- Key files: `db/schema.js` defines all Postgres tables; `db/index.js` is the sole Drizzle client instance (import `db` from here, never instantiate a new client)
- Enforced by SvelteKit convention: anything under `server/` is stripped from client bundles automatically

**`src/lib/components/`:**
- Purpose: All Svelte UI, organized by atomic-design tier
- Contains: `atoms/` (no sub-component composition), `molecules/` (compose atoms + own local interaction logic), `chrome/` (single app-shell component), `effects/` (ambient/decorative, no business logic)
- Key files: `molecules/DraftBoard.svelte` (drafting phase UI), `molecules/LobbyHostBar.svelte` (host controls + `DraftSettingsPanel`), `chrome/CyShell.svelte` (header/phase tracker wrapper)

**`src/routes/`:**
- Purpose: SvelteKit file-based routing — pages, layouts, server load/actions
- Contains: three routes (`/`, `/login`, `/draft/[id]`) plus a `demo` scaffold route
- Key files: `draft/[id]/+page.svelte` is the largest and most central client file (~400 lines, all lobby/draft/chat UI and RPC wiring)

**`drizzle/`:**
- Purpose: Generated migration SQL and schema snapshots
- Contains: numbered `.sql` files + `meta/_journal.json` + per-migration `meta/*_snapshot.json`
- Generated: Yes (via `npm run db:generate`) — do not hand-edit `.sql` files after they've been applied; add a new migration instead

**`design_handoff_pickban_cyber/`:**
- Purpose: Standalone static HTML/CSS/JS design prototype (cyberpunk pick/ban visual reference), used as a design source, not imported by the SvelteKit app
- Contains: `prototype/shared/`, `prototype/variants/`
- Not part of the build graph — do not import from `src/`

**`build/`:**
- Purpose: Production build output from `vite build` (adapter-uws layout: `build/client/_app/immutable/*`, `build/server/chunks/*`)
- Generated: Yes — regenerated on every build, safe to delete

## Key File Locations

**Entry Points:**
- `src/hooks.server.js`: HTTP request pipeline (guest cookie + Better Auth session)
- `src/hooks.ws.js`: WebSocket upgrade/auth resolution + `live.auth.refreshSession`
- `src/routes/+layout.svelte`: root UI wrapper for every page

**Configuration:**
- `svelte.config.js`: adapter (`svelte-adapter-uws`) + Svelte runes compile mode
- `vite.config.js`: plugin list, `$live` watch-ignore rule, vitest browser/server test projects
- `drizzle.config.js`: migration generator config
- `.env` / `.env.example`: `DATABASE_URL`, `BETTER_AUTH_SECRET`, `ORIGIN`, Discord OAuth vars (existence noted only — contents not read)

**Core Logic:**
- `src/lib/server/rooms.js`: room/team/host business rules
- `src/lib/server/draft.js`: draft action + snapshot assembly + race-safe turn advance
- `src/live/room.js`, `src/live/draft.js`, `src/live/chat.js`: realtime RPC surface

**Testing:**
- Co-located `*.spec.js` / `*.svelte.spec.js` files next to their source throughout `src/lib/`, `src/live/`, `src/routes/`
- `src/lib/draft/__tests__/`: dedicated integration test directory for disconnect and snapshot scenarios
- Root-level `src/phase8-foundation.spec.js`, `src/phase10-screens.spec.js`, `src/phase11-fixes.spec.js`: cross-cutting regression suites named after delivery phases (not co-located with a single source file)

## Naming Conventions

**Files:**
- SvelteKit convention files: `+page.svelte`, `+page.server.js`, `+layout.svelte` (framework-mandated names, lowercase with leading `+`)
- Domain/server modules: lowercase-kebab or lowercase-plain `.js` (`room-lifecycle.js`, `draft-timers.js`, `chat-filter.js`, `join-parse.js`)
- Svelte components: PascalCase `.svelte` (`DraftBoard.svelte`, `ChampionCard.svelte`, `CyShell.svelte`)
- Tests: co-located, same basename with `.spec.js` (plain JS) or `.svelte.spec.js` (component/browser tests); a `.test.svelte` suffix is used for Svelte-based test host components (`CyModalHost.test.svelte`, `DraftSettingsPanelHost.test.svelte`)
- `Cy`-prefixed components (`CyShell`, `CyModal`, `CyLogo`, `CyShader`) denote the "cyberpunk" visual theme layer

**Directories:**
- `src/lib/components/{atoms,molecules,chrome,effects}`: atomic-design tiers
- `src/lib/server/`: server-only boundary (SvelteKit strips this from client bundles)
- `src/live/`: realtime-layer boundary (recognized by `svelte-realtime` tooling)
- `__tests__/`: reserved for multi-file integration test suites, as opposed to co-located single-file specs

## Where to Add New Code

**New live RPC or stream (new realtime feature):**
- Implementation: add to the relevant existing file in `src/live/` (`room.js` for lobby/host ops, `draft.js` for in-draft actions, `chat.js` for messaging) or create a new `src/live/<feature>.js` module
- Domain logic: put DB queries and business rules in a new or existing `src/lib/server/<feature>.js` module, imported by the live handler — keep `src/live/*` thin (auth check → domain call → publish)
- Tests: co-locate `src/live/<feature>.spec.js` (server vitest project, per `vite.config.js`)

**New page/route:**
- Primary code: `src/routes/<route>/+page.svelte` + `+page.server.js` if server load/actions are needed
- Tests: co-locate `page.server.spec.js` next to `+page.server.js` (see existing pattern in `src/routes/draft/[id]/` and `src/routes/login/`)

**New UI component:**
- Single-purpose, no composition: `src/lib/components/atoms/`
- Composes atoms / owns interaction logic for a UI section: `src/lib/components/molecules/`
- App-shell-level (affects every page): `src/lib/components/chrome/`
- Purely decorative/ambient, no data dependencies: `src/lib/components/effects/`
- Tests: co-locate `<Name>.svelte.spec.js` (browser/vitest-browser-svelte project)

**New DB table/column:**
- Add to `src/lib/server/db/schema.js` (or extend `auth.schema.js` only via `npm run auth:schema` regeneration — do not hand-edit that file)
- Run `npm run db:generate` to produce a new file in `drizzle/`, then `npm run db:push`/`db:migrate` to apply

**Shared utilities:**
- Framework-agnostic helpers usable by both client and server: `src/lib/*.js` (e.g., `join-parse.js`, `draft-script.js`, `chat-filter.js`)
- Server-only helpers: `src/lib/server/*.js`

## Special Directories

**`.svelte-kit/`:**
- Purpose: SvelteKit-generated types and route manifest
- Generated: Yes
- Committed: No

**`build/`:**
- Purpose: Production build artifacts (adapter-uws output)
- Generated: Yes
- Committed: No (should be gitignored; verify `.gitignore` before assuming clean state)

**`src/live/$types.d.ts`:**
- Purpose: Type definitions generated by `svelte-realtime` by scanning `src/live/*.js` exports
- Generated: Yes, on every dev-server file-system scan of `src/live/`
- Committed: Check repo state before assuming — `vite.config.js` explicitly excludes it from the dev-server watch list to prevent an infinite regenerate/reload loop

**`design_handoff_pickban_cyber/`:**
- Purpose: Static design prototype for visual reference, decoupled from the app's build
- Generated: No (hand-authored prototype)
- Committed: Yes, but not part of `src/` — do not wire it into SvelteKit routing

**`src/lib/vitest-examples/`:**
- Purpose: Leftover scaffold example tests from `sv create` (Welcome.svelte, greet.js) demonstrating vitest-browser-svelte usage
- Generated: No (hand-authored scaffold)
- Committed: Yes — treat as reference/template only, not product code
